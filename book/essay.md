# A Library

This book contains all {books} books on my shelves, as of {date}. I generally like to just alphabetize them, so that is how they show up here (John Man’s *Alphabeta* tells where those 26 letters came from).

I have read a lot. A lot about technology, design, food (one of my favorite “design” books is actually *Fäviken*, a cookbook), sustainability, and how we consider the ethics of creating and “problem solving” out in the world (see Victor Papanek’s *Design for the Real World*). I also like to make things. Why not make something about all the books that I have read (or at least intend to read!)?

Books are wonderful objects. You buy one (find one, are gifted one, etc.), read it, notate in it, perhaps do more things with it (sometimes deconstruct it and decoupage a dresser?), and pass it on, and its ideas continue finding new audiences. Old books becomes incredibly useful in a new context (or just stay useful due to the clarity and quality of their information regardless of context). Reading stays a great way to take in information, and keeping books allows one to collect knowledge and “prove” said knowledge is important. I haven't read every book on my shelves. You can't read everything. It still helps to have them, and to know more or less what is in them (as Pierre Bayard says in *How to Talk About Books You Haven’t Read*, “Being cultivated is a matter not of having read any book in particular, but of being able to find your bearings within books as a system”). 

The spines are drawn at {scale} of their real size, from two numbers: how tall the book is, and how thick. I found the height of {height_known}. The other {height_guessed} heights are guesses (I will be measuring them as time allows). Thickness is hard to find too — only {thick_known} came with a known measurement. For {thick_from_pages} more, a short rule worked it out from the page count. The other {thick_guessed} are guesses, and a rule made those too. Designing with rules like these is what Casey Reas and Chandler McWilliams’s *Form + Code* is about.

I didn’t draw the spines. Nor did I work with the traditional software tools for page layout — Illustrator, InDesign, Affinity, Inkscape, Scribus, etc. The catalog predominantly lives in a database and some template files. I mainly used VS Code and a web browser to design it. A script turns the database into a website (library.wjerk.shop), and the same data then feeds a different folder of html and css and python files and becomes this book. Another script lines up the spines, starts a new stretch of shelf when one fills, and cuts a title back to its last whole word when it just won’t fit. I wrote the rules, Claude Code turned the rules into scripts, and the scripts make the pages. (The *Conditional Design Workbook* works the same way: rules first, and the rules make the drawings.) When a page looks wrong, I change the rules (and maybe an html or css template) to improve it.

A design system is a set of written-down decisions: these colors, this type, this grid. I have been trying to build a clearer personal design system so I don't have to make the same decision twice where possible. This way a script, an assistant, or even an AI can make a decision the way I would. Karl Gerstner put it best in *Designing Programmes*: “Instead of solutions for problems, programmes for solutions.” It holds my taste, so I can spend my attention (hopefully) more wisely. And more rapidly start a design problem with my base set of design ideas.

The tools are open. Thirteen typefaces set the spines, all under the SIL Open Font License, which lets anyone use, change and share them. The software that set them is open source (The site and scripts live in code repositories on GitHub (a sort of code library!)). Donald Knuth did something like this in the 1970s: unhappy with how his books were typeset, he wrote TeX to set them, and gave it away (*The TeXbook* is its manual). The text is under Creative Commons, which Lawrence Lessig co-founded (*The Future of Ideas* is his case for a commons of ideas). The catalog is a public file anyone can download.

I always try to find out who designed a book. The ones I go back to carry their ideas in the object itself: *The Medium Is the Massage* and the Jerome Agel books after it; *Climates*, where the paper gets thicker as the book goes on, like rising seas; *Eternally Yours*, with one thing going on in the left-hand pages and different narrative in the right. The design of this book is a minor homage to *I Seem to Be a Verb* by Buckminster Fuller and Jerome Agel: where one line of type runs continuously across interior spreads.

The book I have referenced most in my design life is Stewart Brand’s *How Buildings Learn*, even though it is an annoyingly landscape 8.5 by 11 page layout. Buildings keep changing after they are built, and the ordinary ones, the ones regular people adapt without a designer, learn best. This book works the same way. The catalog keeps changing, and the book is rebuilt dynamically. The date included on the cover and here indicates the last time the book was “built.”

Two of the spines on these shelves are records: Brian Eno’s *Discreet Music* and *Music for Airports*. Eno set up tape loops, started them, and let the system make the music. Sol LeWitt wrote that “the idea becomes a machine that makes the art” in “Paragraphs on Conceptual Art” (reprinted in Richard Kostelanetz’s *Esthetics Contemporary*). Lucy Lippard’s *Six Years* documents the conceptual art of those years. This book is a small machine like those, and the machine is easier to build now. Most of the actual code for this project came out of a conversation with Claude Code.

So where do we keep the organic systems that come with designing for people, and for the earth? How do these tools meet our normal equipment and spaces? Ivan Illich’s *Tools for Conviviality* asks the same thing: whether a tool leaves people free to use it their own way. The copies of this book come off a Risograph, onto the blank backs of old paper from my office, and I've trimmed and folded each leaf by hand.

Books are good. I still believe in reading. There's something different getting ideas and content out of bound pages and not just screens, continuous scroll pages, and chat interfaces. 

Good reading, whatever that means to you.
